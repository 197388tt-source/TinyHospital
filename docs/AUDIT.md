- 52 个完全重复文件改为单一实体和恢复映射，包含重复的经验 JSON、空经验文件和历史资源。恢复脚本会在本地生成运行所需隔离副本。

## 研究与复现仍存在的不足

1. **真实药物数量可见**：`count=len(drug_labels)` 传给 Doctor。这是 oracle-count 条件，不能直接声称从对话自主预测药物集合大小。
2. **没有训练权重**：当前 `train` 是 LLM 经验提炼；没有优化器、梯度更新或 embedding 微调。
3. **来源行号脆弱**：经验只存 `case_id`，需要严格绑定训练集哈希与顺序；`provenance.json` 为当前默认快照补充了绑定信息，其他历史版本需分别核对。
4. **阈值未校准**：0.60 为源码注明的保守初值。应该通过验证集选择，不能在测试集反复调参后报告无偏性能。
5. **经验审核不等于临床验证**：成功经验校验主要验证引用存在、格式与长度；反思校验不检查医学事实。还需要人工审核和错误类型分析。
6. **不同模型测试格式不同**：API Doctor 测试只要药名数组，Qwen 还生成并校验理由；跨模型比较时混入提示词、输出 Token 和失败机制差异。
7. **失败样本口径**：当前质量指标排除 null 预测；报告 micro F1 时必须同时展示失败数量，或补全统一的失败计分方案。
8. **原运行环境未冻结**：缺原 Python/torch/transformers/CUDA 版本、模型 revision；本次 requirements 仅补齐可执行依赖说明，不是重建出的原 lockfile。
9. **历史实验并非严格可续跑**：绝对路径、代码指纹、模型和版本不一致；保留记录供离线分析，不承诺更换目录后直接 `--resume`。
10. **语义近重复与患者泄漏未证明排除**：cut 三划分未发现完全相同 dialog 列表，但未做患者分组与语义近重复检查。
11. **性能比较含混杂因素**：真实 API 三种传输实验的预测有差异；不能将所有质量变化归因于通信方式。离线确定性 benchmark 只适合比较传输成本。
12. **通信 Token 不是计费 Token**：正则估算、真实 API usage、Qwen tokenizer 三者不同。共享内存减少 IPC 字节不自动减少 LLM prompt Token。
13. **网关与平台约束**：默认网关可能受校园网络/授权限制，embedding 默认是 HTTP；原生 Windows 的 POSIX 锁/管道不兼容。应在 Linux/WSL2 复现并配置获授权的服务。
14. **数据来源已补核验**：与论文直接链接的公开 DialMed 仓库对比，train/dev 逐字节相同，test 仅一行补全 MASK 右括号。上游 MIT 许可已保留，核验详见 DATA_PROVENANCE.md。公开基准来源不等于医学安全验证，也不等于可以重新识别病例身份。
15. **本地模型能力受限**：Qwen 只接 sync、未实现量化配置、自动下载和分布式推理；显存/速度条件仍需实际 GPU 测试。
