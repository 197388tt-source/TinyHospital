# Tiny Hospital 赛题统一评测报告

固定运行 DIALMED `traincut.txt` 前 10 例。两种模式使用相同的八步医疗协作与确定性角色策略，不访问网络或模型 API；因此可重复比较通信成本，不能将本报告的本机耗时外推为真实 LLM 服务时延。

## 纯文本协作与结构化协议对比

| 指标 | 纯文本协作 | TH-ACP 结构化协作 | 改进 |
| --- | ---: | ---: | ---: |
| 病例数 | 10 | 10 | 一致 |
| 完全匹配病例数 | 0 | 0 | 一致 |
| Agent 间消息数 | 80 | 80 | — |
| 通信字节 | 91557 | 57568 | 节省 33989 (37.12%) |
| 通信 Token 估算 | 31146 | 21858 | 节省 9288 (29.82%) |
| TH-ACP 完整报文字节 | 不适用 | 75081 | 含协议头与关联字段 |
| 每病例本机执行时间 | 1.224 ms | 1.338 ms | 仅供本机参考 |

纯文本模式把任务、病例、结果和药物说明写入自然语言消息；TH-ACP 模式用 capability、结构化参数、关联 ID 和协议校验路由相同业务步骤。两者推荐结果一致，通信开销差异因此可归因于通信表示，而非病例或决策质量变化。

## 非文本状态传递：Doctor → Expert 二进制决策向量

- 覆盖病例：10；实际二进制交接帧：20；输出一致：True。
- JSON 重建帧：5136 字节；二进制实测帧：4872 字节；节省 264 字节（5.14%）。
- 原始二进制状态载荷：530 字节；编码均值 6.38 μs；解码均值 6.20 μs。

## 说明

- Token 为稳定的字符规则估算，不等同于任一模型 API 的实际计费 Token。
- 纯文本模式和结构化模式均执行八个业务交接；TH-ACP 的 `packet_count` 统计业务协议报文。
- 二进制状态传递单独在四 Agent 进程 Runtime 中测量，包含 Pipe 帧头，不包含 LLM 推理时间。
