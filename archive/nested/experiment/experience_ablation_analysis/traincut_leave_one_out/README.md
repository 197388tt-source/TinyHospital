# traincut 经验消融分析

本目录把 `data/traincut.txt` 的 686 个病例在四组已完成实验中按病例 ID 对齐：空经验、仅正向、仅反向、正反都有。四组均使用测试阶段、相同的 Qwen 医生模型和 GLM-Embedding-3 检索配置。检索时排除与当前测试病例 ID 相同的经验。经验库共 559 条（正向 59 条，反向 500 条）。

## 文件

- `summary.json`：四组总体指标、相对空经验的逐病例变化、命中数。
- `per_case.csv`：每个病例各有一行仅正向和仅反向记录，共 1372 行；未命中时经验 ID 与文本留空，仍保留该病例的两组预测供检查。
- `per_experience.csv`：559 条经验各一行；只按**单类实验实际选中**的病例汇总相对空经验的变化。零命中经验保留，平均 F1 变化留空。
- `per_case_both.csv`：正反都有实验的 686 条逐病例记录，列出实际选中的正反经验和相对空经验的变化。
- `per_experience_both.csv`：559 条经验各一行；按**正反都有实验实际选中**的病例汇总相对空经验的变化。正向与反向经验共同影响同一预测，因此这张表表示共同场景中的关联，不能把变化单独归因于其中某条经验。
- `build_analysis.py`：重新生成以上 CSV 和 JSON 的脚本，运行方式为 `python experiment/experience_ablation_analysis/traincut_leave_one_out/build_analysis.py`。

CSV 使用 UTF-8 BOM，便于用表格软件打开。`空经验错→单类对` 等列使用实验保存的完全匹配标记；病例 F1 按药物多重集合计算。`病例F1提高/下降/不变` 是逐病例比较，**不是总体 micro F1 的变化**。预测失败的病例按实验原始结果计入。

`完全正确净变化` = 错→对次数减去对→错次数；`病例F1净提高次数` = 提高次数减去下降次数。它们便于排序筛查，但命中次数少的经验不宜仅凭净值判断质量。

## 解读边界

单类表对比“选中某条经验的运行”和“空经验运行”在同一病例上的输出，可用来筛查可能有益或有害的经验，但模型调用之间仍可能有随机变化，观察到的变化不能单独证明因果。正反都有表尤其不能用于衡量其中一类经验的独立效应。未被检索到的经验没有可观察的命中效果，不应按零效果解读。

正向单类和正反都有两组在全部 686 个病例上的正向来源选择一致（包括 3 个均未命中）；反向来源选择在 684 个病例上一致。分析均使用每组**实际选中**的来源 ID，没有强行把单类选择套到正反都有实验上。
